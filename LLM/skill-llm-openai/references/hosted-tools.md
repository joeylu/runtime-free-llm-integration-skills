# OpenAI Hosted Tools

OpenAI-hosted tools run on the provider side. They are separate from caller-defined `function` tools.

## Core Rules

- Model support in this file is verified only for the Responses API and the three documented GPT-5.6 models.
- Put declarations in shared `HostedTools`, not `Tools`.
- Normalize executions into `HostedToolCalls`, not caller-owned `ToolCalls`.
- The names in the table are normalized tool identities, not guaranteed wire `tools[].type` values. Resolve the exact declaration, configuration, output items, approvals, and errors from that tool's official guide before implementation.
- Do not assume a hosted tool is safe or correctly scoped merely because the model page lists it as supported. Apply the local gating below and keep the request fail-closed until the wire contract is synced.
- Parallel caller-defined function calling is not available when built-in tools are used. Reject the combination or set `parallel_tool_calls = false` after explicit caller intent is resolved.
- Preserve provider item IDs, call IDs, output items, and reasoning items across tool loops.
- Tool-specific pricing is not included in the token-only GPT-5.6 rows in `pricing-matrix.md`.

## Preview and Special Workflows

- Programmatic Tool Calling is a GPT-5.6 Responses workflow. It requires the `programmatic_tool_calling` declaration, eligible tools opted in through `allowed_callers`, and handling for `program`, program-issued calls, and `program_output` items. Preserve each `call_id` and `caller` linkage. Enable only for bounded tool-heavy workflows after representative evaluation.
- Multi-agent orchestration is beta in Responses. This local skill does not enable it by default; add a separately verified provider option and explicit opt-in before use.
